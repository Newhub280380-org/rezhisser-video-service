# Развёртывание на Render (существующий Web Service)

Инструкция для сервиса `rezhisser-video-service`, который **создан вручную**
в панели Render как Web Service (не через Blueprint).

> **Важно:** файл `render.yaml` применяется только к Blueprint-сервисам.
> Вашему сервису, созданному вручную, он **ничего не меняет**. Все
> переменные окружения задаются руками: Render → сервис → **Environment**.

## 1. Обновление (без ключей сервис стартует и ничего не выдумывает)

Для безопасного режима **никаких новых переменных не нужно**. Всё платное по
умолчанию выключено, а запросы на видео, оплату и автоматизацию называют
недостающие переменные вместо фейкового результата.

1. После слияния PR в `main` Render запустит деплой сам (если включён
   Auto-Deploy). Если не запустил: **Manual Deploy → Deploy latest commit**.
2. Проверьте настройки сервиса (Settings):
   - Build Command: `npm install --omit=dev`
   - Start Command: `node src/server.js`
   - Health Check Path: `/api/health`
3. Проверьте, что в Environment **нет** `PAID_GENERATION_ENABLED=true` и
   `VIDEO_PROVIDER` равен `local-simulation` (или переменной нет вовсе).

## 2. Как проверить, что режим безопасный

Откройте в браузере:

- `https://rezhisser-video-service.onrender.com/api/health` должен вернуть:
  ```json
  { "status": "ok", "videoProvider": "local-simulation",
    "realVideoGeneration": false, "paidGenerationEnabled": false }
  ```
- `https://rezhisser-video-service.onrender.com/api/config`: в
  `paid.available` стоит `false`, а в `paid.reasons` перечислено, чего не
  хватает для платного режима. Это нормально и ожидаемо.
- `https://rezhisser-video-service.onrender.com/`: открывается приложение
  «Режиссёр» со значком **«Провайдер не настроен»**. В `integrations` у
  `/api/health` перечислены пустые переменные.

В логах Render при старте будет строка:

```
paid generation: locked (provider_not_configured, paid_generation_disabled, access_control_not_configured, spend_limits_not_configured)
```

## 3. Как пользоваться без ключей

1. Откройте `/` (или `/app/`), нажмите «Заполнить пример» или опишите свой продукт.
2. «Собрать раскадровку». Режиссёр (по правилам, без ИИ) покажет крючок,
   бриф, визуальный стиль, кадры по секундам, промпт и выбранный пресет с
   объяснением.
3. «Запросить рендер». Ответ будет `503 provider_not_configured` со списком
   переменных (`REPLICATE_API_TOKEN`, `SEEDANCE_API_KEY` и других). Ролик не
   создаётся и не сохраняется как успешный.

Деньги не списываются, внешние сервисы не вызываются.

## 4. (Потом, осознанно) Закрытая бета с платной генерацией

Делайте это только когда: выбрана конкретная модель на Replicate, на её
странице (вкладка **API**) проверены поля ввода, модель один раз запущена
вручную на сайте Replicate и записана **реальная цена**. В репозитории ни
одна настоящая модель и ни одна цена не проверены.

1. В Replicate → Billing поставьте **низкий лимит расходов**. Не считайте
   его гарантированным жёстким потолком, пока Replicate не подтвердит это
   для вашего аккаунта.
2. Создайте API-токен Replicate.
3. Сгенерируйте ключ доступа к бете (≥ 24 символов), например командой
   `node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"`.
   Не пишите его в git, в чаты, в ссылки и в код сайта.
4. В Render → Environment добавьте:

   | Переменная | Значение |
   | --- | --- |
   | `VIDEO_PROVIDER` | `replicate` |
   | `REPLICATE_API_TOKEN` | токен (секрет) |
   | `VIDEO_MODEL_PROFILES_JSON` | профили моделей (формат в README), с **вашей** проверенной ценой в `estimatedCostUsd` |
   | `BETA_ACCESS_KEY` | ключ из шага 3 (секрет) |
   | `PAID_DAILY_BUDGET_USD` | например `2` |
   | `PAID_DAILY_JOB_LIMIT` | например `2` |
   | `PAID_TOTAL_JOB_LIMIT` | например `5` |
   | `PUBLIC_ORIGIN` | `https://rezhisser-video-service.onrender.com` |
   | `PAID_GENERATION_ENABLED` | `true`, **последним шагом** |

5. Save → дождитесь деплоя. Если профиль или ключ заданы неверно, сервис не
   запустится, и в логах будет `configuration error: …`.
6. `/api/health` покажет `"paidGenerationEnabled": true`.
7. На сайте нажмите «Вход для беты», введите ключ, выберите режим «Настоящее
   видео», получите оценку, поставьте галочку и подтвердите **один** запуск.
   Сразу проверьте списание в панели Replicate.

Выключить: `PAID_GENERATION_ENABLED=false` (или удалить переменную) → Save.

### Ограничения, о которых нужно помнить

- Сумма в оценке — это **ваша** оценка, а не счёт Replicate.
- Таймаут, отмена, ошибка или перезапуск **могут не вернуть деньги**.
  Начатая генерация может быть оплачена.
- На бесплатном плане Render диск **временный**. При перезапуске, деплое или
  засыпании сбрасываются история задач и счётчики дневного и общего лимита, а
  также все сессии беты. Для надёжных лимитов подключите постоянный диск
  (платный) и укажите его путь в `DATA_DIR`.
- Работайте **одним экземпляром** сервиса: лимиты и сессии не общие между
  экземплярами.
- Один общий ключ — это **не** учётные записи пользователей. Для продажи
  нужны аккаунты, оплата, база данных и хранилище видео (см. README →
  «Before selling to the public»).

## 5. Сайт business-41.pazi.dev

Приложение «Режиссёр» работает на домене Render. **Сайт Pazi в этом
репозитории не менялся**, и его собственный `/app/` — это отдельная вещь.
Следующий шаг делается в проекте Pazi отдельно: либо поставить ссылку на
`https://rezhisser-video-service.onrender.com/app/`, либо вызывать с сайта
Pazi демо-API (`/api/director/plan`, `POST /api/jobs`). CORS для этого
домена уже разрешён. Платные действия с чужого домена недоступны намеренно.

## 6. Если используете Blueprint (новый сервис)

`render.yaml` содержит безопасные значения по умолчанию:
`VIDEO_PROVIDER=local-simulation`, `PAID_GENERATION_ENABLED=false`,
`PAID_DAILY_BUDGET_USD=0`. Секреты объявлены с `sync: false`, их значения
вводятся только в панели.
